# Model Management and Fine-Tuning Guide

This directory holds the deep learning models used by the **StyleLens Retrieval Core** (e.g., CLIP and ResNet). This document guides you through model architecture, saving procedures, loading methods, and downstream embedding updates.

---

## 1. Directory Structure

A model folder (such as `models/clip_best/`) contains two critical files:

*   **`config.json`**: The architectural blueprint. It defines layers, dimension sizes (e.g., 512 for CLIP projections), attention heads, and activation configurations.
*   **`model.safetensors`**: The weights/learned parameters. Stored in the modern, secure, and fast `safetensors` format rather than pickle-based formats (like `.bin` or `.pth`).

---

## 2. Saving a Fine-Tuned Model

When training models using Hugging Face's `transformers` library (as done in `notebooks/03_fine_tuning.ipynb`), save the model state correctly using `save_pretrained`.

### Standard saving code:
```python
# Assuming 'model' is your fine-tuned CLIPModel instance
output_dir = "models/clip_best"

# 1. Save the model weights and config
model.save_pretrained(
    output_dir,
    safe_serialization=True  # Forces saving as model.safetensors instead of pytorch_model.bin
)
```

### Why we do NOT save the Processor configuration:
*   The **model** (`CLIPModel`) contains the trainable parameters updated during fine-tuning (e.g., understanding fashion attributes).
*   The **processor** (`CLIPProcessor`) is stateless; it only handles text tokenization (fixed vocabulary) and image resizing (static dimensions like 224x224).
*   Because the preprocessing steps do not change after training, you do **not** need to save the processor locally. Instead, load the standard processor directly from Hugging Face.

---

## 3. Loading the Model in Code

To load your fine-tuned model alongside the standard processor, use the following pattern:

```python
import os
from transformers import CLIPModel, CLIPProcessor

model_dir = "models/clip_best"
base_model_id = "openai/clip-vit-base-patch32"

# Load the local fine-tuned weights
if os.path.exists(model_dir):
    model = CLIPModel.from_pretrained(model_dir).eval().to(device)
else:
    # Fallback to the base model if local weights aren't trained yet
    model = CLIPModel.from_pretrained(base_model_id).eval().to(device)

# Load the processor using the base model ID (saves space, keeps settings consistent)
processor = CLIPProcessor.from_pretrained(base_model_id)
```

## 4. Critical Downstream Step: Re-Generating the Gallery Embeddings

Whenever you fine-tune a model or update the weights in `models/clip_best/`, you **MUST re-generate the pre-computed gallery embeddings**. 

If the database is not re-generated:
1.  The gallery database will still contain vectors generated by the **old** model weights.
2.  The **new** model will encode user queries differently.
3.  Because the query space and the gallery space are no longer aligned, search accuracy and similarity scores will drop significantly.

### To re-generate:
Ensure your script encodes the entire clothing gallery dataset through the new model and saves the updated matrix to `embeddings/trained_clip_gallery.npy`:

```python
import numpy as np

# 1. Encode all images in the gallery using the new model weights
gallery_embeddings = []
for img_path in gallery_paths:
    img_emb = embed_image_clip_with_new_model(img_path)
    gallery_embeddings.append(img_emb)

# 2. Save the updated matrix to the embeddings directory
np.save("embeddings/trained_clip_gallery.npy", np.array(gallery_embeddings))
```
